# Запрос модели для P1-03

Представь, что ты профессиональный архитектор ПО и умеешь писать ADR файлы.
Посмотри PR TRAINING_PR.diff и context.md.
Твоя задача заполнить файлы документации в соответствии со следующим списком.

- context.md - AS IS: продуктовый и командный контекст, источники и ограничения
- problem.md - пользователь, проблема и измеримые продуктовые метрики
- analysis.md - AS IS и TO BE процесса в выбранной нотации
- product_management.md - use cases, user stories и сценарии
- project_management.md - инкременты, роли людей/AI и план поставки
- adr.md - архитектурное решение и Mermaid-схема
- tests_unit.md - unit-проверки
- tests_integration.md - integration-проверки
- tests_load.md - нагрузочные проверки и ожидаемые пределы
- tests_e2e.md - сквозные сценарии
- prompts.md (P1-03) - запросы, результаты, ссылки на изменённые артефакты и собственная оценка

Тебе запрещено изменять TRAINING_PR.diff. Все остальные указанные файлы можешь изменять
Для начала изучи их текущее содержимое, затем дополни/заполни его в соответствии с требованиями.
Твой flow: выбор файла -> изучение содержимого -> заполнение -> проверка.
Итог: все файлы заполнены.
