# Проблема и метрики

## Проблема

- Пользователь: инженер по качеству/ревьюер, CI-сервис, вызывающий ассистента ревью.
- Ситуация: сервис получает diff PR, отправляет его во внешний LLM и возвращает результат через FastAPI.
- Что происходит сейчас: реализован прямой прокси-вызов LLM без маскировки секретов, без ограничений длины diff, без таймаута/обработки ошибок, и с несоответствием формата ответа требованиям.
- Почему это мешает пользователю или бизнесу: риск утечки секретов (SEC-1), нестабильность и подвисания при деградации LLM (REL-1), невозможность интеграции из-за несоответствия контракту ответа (OUT-1), потенциальные отказы по превышению размера без корректного HTTP 413 (API-1).
- Что не входит в задачу: реализация интеграции с GitHub (approve/merge), изменение БД.

## Метрики

Выберите измеримые показатели, относящиеся к проблеме. Не используйте VTG, IRR, WACC, CSAT или другую метрику только ради названия.

| Метрика                                                 |       Текущее значение или способ замера |        Целевое изменение | Когда измеряем               | Источник данных             |
| ------------------------------------------------------- | ---------------------------------------: | -----------------------: | ---------------------------- | --------------------------- |
| Доля ответов, соответствующих OUT-1 (schema compliance) | < 10% (возврат `{comment}` по умолчанию) |                    ≥ 99% | На каждом релизе/в CI        | Контрактные тесты API       |
| Процент запросов к LLM, завершённых за ≤10 сек          |                        Не контролируется |                    ≥ 99% | В нагрузочном тесте          | Тайминги и метрики таймаута |
| Кол-во обнаруженных «сырых» секретов в prompt           |                          Потенциально >0 |                        0 | В юнит/интеграционных тестах | Тестовые диффы с секретами  |
| Доля отклонённых длинных diff с HTTP 413                |                        Не контролируется | 100% при >20000 символов | Тест API                     | Интеграционные тесты        |

Соответствие OUT-1 гарантирует, что потребители API могут парсить и использовать результаты. Таймаут и ограничение по времени повышают надёжность и предотвращают зависания. Нулевая утечка секретов в prompt снижает риск инцидентов безопасности. Корректный HTTP 413 обеспечивает предсказуемое поведение при больших входах.
